# 检查点实验台

一个零 Kafka、零云服务、零外置数据库的本地流处理检查点演示项目。项目使用 TypeScript + Vite + Vitest，核心引擎同时可在浏览器 `localStorage` 和 Node 文件存储上运行。

## 安装与运行

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm test -- --run
pnpm dev -- --host 127.0.0.1 --port 5219
```

打开：<http://127.0.0.1:5219>

## 演示的一致性语义

- 每个分区内事件严格按 offset 处理；分区间只做稳定轮转展示和调度，不存在全局到达顺序提交语义。
- 单次投递中，聚合状态写入与分区 offset 提交位于同一内存事务边界；在边界前崩溃会同时丢弃两者。
- 重复事件可以再次进入处理器；处理器记录“至少一次处理次数”，但通过幂等键集合保证最终状态只变更一次。
- 检查点包含分区提交进度、输入日志高水位、聚合状态、处理器版本和处理指标。
- 检查点先写临时目录/临时键，完整后再 rename；恢复只读取带完成标记且语义哈希通过的检查点。
- 处理器版本不兼容时拒绝直接启动，只能通过显式迁移创建新检查点；迁移失败只追加失败记录，不修改旧检查点。
- 实验导出包含事件、检查点、迁移记录、最终进度、最终高水位和语义哈希；空实例重放后可验证哈希一致。

## 页面操作

1. 创建一个或多个分区。
2. 向分区追加带 offset（自动分配）、key、value 和可选自定义幂等键的事件。
3. 使用启动、暂停、继续、单步、批量消费或消费全部观察状态。
4. 在预设位置注入一次性崩溃：写状态前、写状态后、提交 offset 前、检查点写入前、检查点 rename 前/后。
5. 崩溃后点击“启动 / 崩溃后重启”，系统只恢复最后一个完整检查点。
6. 比较“至少一次处理次数”“重复幂等投递”和“有效状态变更次数”。
7. 使用 v1/v2 显式迁移，可勾选模拟失败以验证原检查点回滚。
8. 导出 JSON，在空实例通过“导入并重放”恢复到相同状态哈希。

## 代码结构

- `src/core/types.ts`：事件、状态、检查点、迁移和实验导出类型。
- `src/core/processors.ts`：聚合处理器、幂等键去重、v1 到 v2 状态迁移。
- `src/core/checkpoint.ts`：稳定规范序列化与 SHA-256 语义哈希。
- `src/core/engine.ts`：消费事务、检查点、崩溃恢复、版本迁移、导入与确定性重放。
- `src/node/file-storage.ts`：测试使用的原子文件检查点存储。
- `src/browser/local-storage.ts`：网页使用的持久化适配器。
- `src/main.ts`、`index.html`、`src/style.css`：检查点实验台界面。
- `tests/engine.test.ts`：故障注入、幂等、分区独立推进、迁移回滚和重放哈希测试。
